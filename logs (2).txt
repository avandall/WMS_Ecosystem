📊 Cách thiết kế chi tiết các chỉ số trong Section 1
Để gãi đúng chỗ ngứa về Data Ingestion của các công ty AI/Big Data, biểu đồ của bạn phải thể hiện được sự khác biệt cơ bản giữa việc Xử lý đồng bộ thông thường (Sync - nghẽn cổ chai) và Xử lý bất đồng bộ qua Hàng đợi (Async với Redis Streams).

Bạn nên thiết kế giao diện hiển thị 2 kịch bản (được trích xuất từ dữ liệu chạy thật trên máy bạn):

1. Chỉ số đo tải (Throughput & Latency Metrics)
Sync Processing Pipeline (Không dùng Message Queue): Khi kéo tải lên quá 500 RPS (Requests Per Second), thời gian phản hồi (Response Latency) tăng vọt theo hình parabol (từ 50ms lên 5,000ms) và bắt đầu xuất hiện lỗi HTTP 504 Gateway Timeout hoặc Connection Pool Timeout do Database bị block.  
MD
+ 1

Async Ingestion Pipeline (FastAPI Gateway → Redis Streams): Khi kéo tải lên tới 5,000+ RPS, thời gian phản hồi của Gateway vẫn đi ngang một đường thẳng tuyệt đối ở mức < 10ms. Lý do là Gateway chỉ làm đúng một việc: Nhận JSON packet, đẩy vào Redis Streams và trả về HTTP 202 Accepted ngay lập tức.

+ 3

2. Chỉ số toàn vẹn dữ liệu (Data Integrity Metrics) - Điểm ăn tiền nhất
Event Dropped Rate: Hiển thị số lượng sự kiện bị mất mát. Trong mô hình Sync khi tải quá cao, số này sẽ tăng (ví dụ: dropped 15%). Với mô hình Async dùng Redis Streams, biểu đồ phải chỉ ra: Dropped Events = 0 (100% Ingestion Success).  
MD
+ 1

Consumer Backlog Status: Biểu đồ này hiển thị số lượng message đang xếp hàng trong Redis Streams chờ inventory-service (hoặc các worker) tiêu thụ. Khi tải đạt đỉnh, queue sẽ phình to ra, và sau đó giảm dần khi các async worker xử lý dần dần (Xử lý mượt mà đỉnh tải - Peak Shaving).

import asyncio
import httpx
import time
import random
import uuid

TARGET_URL = "http://localhost:8000/api/v1/inventory/ingest"  # api-gateway endpoint

async def send_sensor_data(client: httpx.AsyncClient, worker_id: int):
    """Giả lập 1 thiết bị quét mã/robot gửi event liên tục về hệ thống"""
    # Tạo dữ liệu giả lập giống hệt hệ thống WMS thực tế
    payload = {
        "idempotency_key": str(uuid.uuid4()),
        "sku": f"SKU-AI-MODEL-{random.randint(100, 105)}",
        "quantity": random.randint(1, 10),
        "trace_id": f"trace-{uuid.uuid4().hex[:8]}"
    }
    
    start_time = time.perf_counter()
    try:
        response = await client.post(TARGET_URL, json=payload, timeout=2.0)
        latency = time.perf_counter() - start_time
        return response.status_code, latency
    except Exception:
        return 500, time.perf_counter() - start_time

async def start_traffic_simulator(total_requests: int, concurrency: int):
    print(f"🚀 Starting Traffic Simulator: Sending {total_requests} events with concurrency={concurrency}")
    
    limits = httpx.Limits(max_keepalive_connections=concurrency, max_connections=concurrency)
    async with httpx.AsyncClient(limits=limits) as client:
        tasks = [send_sensor_data(client, i) for i in range(total_requests)]
        
        start_bench = time.perf_counter()
        results = await asyncio.gather(*tasks)
        total_time = time.perf_counter() - start_bench
        
        # Thống kê số liệu thực tế để đưa vào Portfolio
        status_codes = [r[0] for r in results]
        latencies = [r[1] for r in results]
        
        success_count = status_codes.count(202)  # 202 Accepted từ Async Pipeline
        error_count = len(status_codes) - success_count
        avg_latency = sum(latencies) / len(latencies)
        rps = total_requests / total_time
        
        print("\n📊 --- REAL BENCHMARK REPORT ---")
        print(f"Execution Time: {total_time:.2f} seconds")
        print(f"Throughput: {rps:.2f} Requests/Second (RPS)")
        print(f"Average Latency: {avg_latency * 1000:.2f} ms")
        print(f"Success Rate: {(success_count/total_requests)*100: .2f}% | Dropped: {error_count}")

if __name__ == "__main__":
    # Chạy trên môi trường WSL để lấy chỉ số thực tế cho hệ thống WMS của bạn
    asyncio.run(start_traffic_simulator(total_requests=5000, concurrency=500))
